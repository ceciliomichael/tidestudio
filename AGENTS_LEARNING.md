# User Preferences

- Keep responses concise, direct, and in English.
- For TideStudio development, plan before implementation and keep plans under `docs/plan/`.
- TideStudio UI should feel calm, precise, restrained, and deliberate, with hierarchy driven by spacing, typography, alignment, and fine separators rather than decoration.
- TideStudio should visibly use TideCode's deep green primary action and soft green selected-state palette while keeping large content areas light, ordinary metadata badges neutral, and warning/danger treatments semantic.
- Settings follows TideCode's General settings hierarchy by replacing the normal main sidebar with a dedicated Settings sidebar for General and Updates. General contains only Appearance (Light/Dark/System using the shared SegmentedField) and Preferences (language); persist selections across launches.
- Keep Settings to two panels and use the shared `ResizableWorkspace` with a dedicated `settings` mode, not `modelSearchBrowse` (which disables left resizing). Retain the default sidebar width and constraints across page navigation; Settings main retains the normal surface border and top-left radius.
- Tauri `Window.setBackgroundColor` does **not** recolor the Windows native title bar. Set its theme with `Window.setTheme`, then apply DWM caption/border/text colors via a Windows-only Rust command, drawing the caption fill from `--color-sidebar` (`#f0f0f0` light; `#141415` dark). On unsupported OS versions allow standard native caption styling.
- The API gateway may be alive on the public port but show `API stopped` when an orphaned process belongs to a previous TideStudio instance. Verify gateway PID, parent PID, executable path and `/health` before touching processes. Windows gateway children must supervise the owning TideStudio process (passed through `TIDE_GATEWAY_PARENT_PID`); Rust should reject occupied ports explicitly and never silently adopt or kill unrelated listeners. Rebuild the Go gateway binary and restart the native app after changes.
- General Settings sections must reset the legacy `.settings-section { min-height: 100%; padding: ... }` via `.settings-content > .settings-section { min-height: 0; padding: 0; }`. Otherwise Appearance fills the workspace height and pushes Preferences far away; use the intended 20px gap between stacked sections.
- Match TideCode's exact neutral-charcoal dark palette. Balance segmented sizes by context: shared/general, Model Inspector tabs and Settings Theme 14px / 32px; Supported Endpoints 13px / 30px; compact Load Model sorting 14px / 18px options. Load Model sorting and Settings Theme are content-sized with 56px minimum options, not wide fixed fields. Keep active text dark in light mode and white in dark mode.
- Do not force all segmented controls to a single large size. Adjust option padding, gap and icons proportionally for each context.
- Keep segmented-field inner spacing balanced: 3px container padding on every side and 3px gap between options, with rounded 12px outer / 8px inner corner radii across features.
- Use `--switch-off-track` for unchecked `.tide-switch`: light gray `#d8d8d8` in light mode and charcoal `#3f3f42` in dark mode, with a white thumb in both. Do not replace the theme-specific green checked state or alter the switch's dimensions/animation.
- Do not use generic descendant `span` typography selectors in the Load Model heading; they can override segmented option labels and active/inactive colors. The heading no longer contains a model-count label.
- Supported Endpoints and unselected loaded-model cards share the same `--loaded-card-border` token, `#36363a` in dark mode; selected loaded models retain their green border.
- Primary sidebar navigation text should be near-black in light mode and white in dark mode rather than using the green brand color for the active label.
- In dark mode, server logs need high-contrast light text on a near-black terminal surface, and loaded-model cards should stay neutral-charcoal with restrained green only for selection.
- Prefer nearly black loaded-model cards in dark mode; use the green border, not a green card fill, to show selection. Match TideCode Settings desktop alignment with centered 780px content, 64px top spacing, compact rows, content-sized theme segments, and a 240px language dropdown.
- Prefer flat solid surfaces and open layouts. Avoid gradients, glass effects, heavy shadows, and unnecessary cards.
- Use a consistent icon library for interface icons. Do not use emoji as UI icons.
- Structure the TideStudio desktop workspace around a compact roughly 220px resizable navigation rail, one continuous primary work surface, and a contextual right inspector when needed.
- Keep an `InferenceBackend` architecture boundary so llama.cpp is one backend implementation rather than being coupled directly to the server registry.
- For the Models right inspector, use an LM-Studio-like Info / Load / Inference hierarchy with TideCode-style segmented controls, while keeping TideStudio's own light visual system.
- Keep Models settings model-specific. Server/network settings such as port belong on Server. Models should support llama.cpp model/inference features such as MTP and speculative drafting when the bundled runtime supports them.
- The Models Inference tab should expose practical LM-Studio-like prompt, reasoning, and sampling defaults. Only show reasoning controls for models marked reasoning-capable, and do not fake unsupported llama.cpp launch flags.
- Prompt Template belongs at the bottom of Models > Load, not Inference. Leave it empty to use the GGUF-embedded chat template when available.
- Prompt Template should use a multiline field. When GGUF metadata parsing exists, prefill/surface the embedded `tokenizer.chat_template` and allow the user to override it.
- Server workspace should expose only the OpenAI-compatible and Anthropic-compatible families in Supported Endpoints. Do not add a TideStudio/native segment.
- Supported Endpoints should default to collapsed and persist its collapsed/open state in SQLite.
- Server-wide settings should open from the Server Settings toolbar action, not occupy the right inspector. The Server right inspector should stay model-focused and show the selected loaded model's Info / Load / Inference tabs.
- Server Settings has no title row or upper-right X: use `Modal.hideHeader` to remove the header structurally while preserving the accessible dialog title, Escape/outside-click dismissal, top body padding, and Cancel/Apply footer. Other modals retain their headers unless explicitly opted out.
- Size Server Settings responsively to the viewport with a 960px by 800px maximum and 72px window clearance. Keep internal body scrolling and the Cancel/Apply footer fixed at the bottom of the modal; do not let the modal overflow a shorter window.
- Load Model on Server should open a model-manager dialog with Currently Loaded and Your Models sections rather than navigating to the Models page.
- Model Search should support real GGUF repository providers behind one source selector. Hugging Face is the default source and ModelScope is also supported, with file-level downloads, progress, and post-download capability inspection.
- Model Search should fill the center panel, with its search/header area fixed and only the repository list vertically scrollable.
- The repository browser is visibly named Model Search. Search is debounced without a submit button, the active provider is selected beside the search field, and global download progress belongs in the separate Downloads page rather than inside Model Search.
- Navigation uses separate `modelSearch` and `downloads` page IDs: do not route the Model Search repository browser under `downloads`. Put Downloads where disabled Presets used to be, showing a live count badge; anchor Settings to the sidebar bottom without a dividing border. Downloads and Settings use two-pane layout modes; Model Search still expands its right detail pane when a repository is selected.
- Apply a fine `--color-border-muted` top border only to the center and right inspector panels. Keep both left sidebars (`.navigation-panel` and `.settings-sidebar`) free of top borders, preserve the main panel's rounded top-left corner, and do not add a divider above the bottom Settings navigation button.
- Model Search should use an LM Studio-like two-panel information hierarchy: search/results in the center and detailed repository stats, download options, capabilities, and README in the separate right inspector.
- Model Search Download Options should present GGUF quantizations in a dropdown with one Download button, and separate vision projector files in their own dropdown.
- Model Search browse mode should collapse the right pane until a repository is clicked. Selecting one should expand the detail pane to a majority of the usable workspace; closing the detail pane should restore the wide list view.
- Model Search file buttons should show live percentage while downloading. Global download activity should throttle visible updates and keep speed/byte metrics stable and readable.
- Real GGUF models should prefill Load > Prompt Template from embedded `tokenizer.chat_template`; unchanged embedded templates are model defaults, not explicit overrides.
- Models and Server should not use preview/mock model data. Both should derive from real discovered GGUF files and real managed llama-server processes.
- Capability detection should prefer GGUF metadata and embedded chat-template evidence, then use repository/model heuristics with explicit confidence rather than claiming unsupported certainty.
- MTP support is a capability, not a model category. A normal MTP-capable target model must remain an LLM; reserve Drafter classification for explicit draft/EAGLE-style companion models.
- Native decision GGUFs are a distinct `DECISION` model category. Prefer GGUF decision metadata such as `modern-bert.decision.*` or `decision-model` tags over filename heuristics.
- Laya decision GGUFs use `laya.*` metadata and may report `general.architecture=ggmlc`; classify those as `DECISION` even if the bundled llama.cpp runtime cannot load that architecture yet.
- GGUF parameter display must not depend only on `general.size_label`. Prefer `general.size_label`, then `general.parameter_count`, then derive the count from GGUF tensor dimensions without loading tensor data.
- Models table columns should be Model, Publisher, Type, Params, Quant, Context Length, Size, and Actions. Keep rows compact, truncate long model names, and keep Actions aligned to the far-right edge. Do not show a redundant GGUF format label because all managed model files are GGUF.
- Models table keeps model data and a fixed 72px Actions pane as separate siblings. Actions must stay outside horizontal scrolling entirely. Synchronize their vertical scroll positions, use matching 30px headers and 44px rows, and mirror hover/selection. Use one absolutely bottom-anchored horizontal scrollbar across the full table width as the sole horizontal authority. Do not synchronize two horizontal scroll containers bidirectionally; instead translate the model header and body content from the scrollbar's single shared offset so the far-right endpoint cannot snap. Data rows use `padding-inline: 20px 0`; the 12px Actions right gutter belongs inside its fixed pane.
- Anchor the three-dot Actions button in a 20px square inside the sticky cell, center its 14px icon, and avoid an extra positioned/z-index wrapper; the dropdown itself renders through a portal.
- Model Search list badges should fit one visible row at the current panel width, with GGUF and Vision/Text first and then only complete extra tags that fit. Use wrapping with one visible line and no JavaScript resize measurements.
- MoE Params should preserve or derive the expert layout, for example `64x1.2B`, rather than flattening it to only a total parameter count.
- Disable the WebView/browser native context menu across the desktop app. Model-specific actions belong in TideStudio's own Actions menu.
- Model deletion must be limited to managed GGUFs and remove the sibling TideStudio settings sidecar with the model. If the GGUF is currently loaded, stop/unregister its worker automatically before deleting it.
- New MTP-capable GGUFs default to MTP speculative mode unless a saved per-model sidecar overrides that default.
- Models classified as Embedding should launch in llama.cpp `--embeddings` mode automatically and expose pooling instead of chat-generation controls. GGUF rank pooling means reranking, not ordinary dense embeddings.
- TideStudio public API routing uses the Go-based API gateway under `studio/api-gateway/` in front of private loopback llama.cpp workers, with one public port and OpenAI, Anthropic, and TypeSafe System One compatibility; Rust/Tauri remains the desktop/process integration layer.
- TideStudio should use a readable desktop type scale. Raise explicit small CSS declarations, not just `body`: main labels 14–15px, helpers/metadata 12–13px, buttons/inputs 13–14px, badges at least 11px; adapt row heights and preserve overflow/truncation in dense tables and inspectors.
- Keep loaded-model entries as a two-row component: state/chevron on the first row, model identity/capabilities and RAM/Stop actions on the second row.
- Loading a model must not block TideStudio UI or depend on API gateway readiness. Show the worker immediately as Loading, transition it to Ready when the worker itself is healthy, then register it with the gateway asynchronously when available. Gateway startup/reconfiguration must reconcile already-ready workers.
- Background gateway startup must not hold the gateway mutex across health polling, and gateway status commands must not synchronously block the Tauri UI command thread.
- Model loading is optimistic in the Server UI: clicking Load closes the modal and immediately inserts a pending Loading card before the Rust start command returns. Replace that pending card with the real worker status once spawn succeeds.
- Keep the Load Model dialog compact and dense rather than a near-full-workspace modal. Position it toward the upper window area. Its search input lives in a 50px custom `Modal.headerContent`, replacing the title bar and separate search row; the modal still has its accessible `Load Model` title, rounded corners, and Escape/outside-click closing. Use `Modal.hideCloseButton` only for this modal and place a single X inside the search header: clear the filter if nonempty, otherwise close the dialog. The same X remains visible for both states and its accessible label reflects the action. Remove the count next to `Your Models`, and place the sort segmented field in a 38px heading at about 26px total height (18px options, 3px gap/inset, 14px labels, reduced 8px outer/5px inner radii). Do not add a full-width gray strip or a heading bottom border; the first model row's top border provides the separator. Preserve the dense list, inline metadata, and compact Loading/Stop state.
- For the Load Model modal combined clear/close X, explicitly size and center the 26px button and 16px SVG, resetting inherited padding/line-height and keeping the icon block-level. Remove the idle border, background, and inset shadow from this control only, but retain the shared subtle hover highlight. Shared icon-button overrides can otherwise disrupt the compact search header.
- In the Load Model picker, make the entire unloaded model row clickable instead of showing a dedicated Load button.
- Supported Endpoints should read as a wide floating rounded utility panel, while its segmented control remains compact.
- Server RAM polling should refresh only the managed worker PID rather than scanning all system processes.
- Persist each GGUF's Load and Inference configuration beside the exact model as `<model>.gguf.tidestudio.json`, with separate load/inference sections.
- Loaded-model Inference changes should apply to subsequent requests immediately where request-time overrides are supported; Load settings remain next-load settings.
- Explicit inference request fields must override TideStudio's saved per-model defaults.
- Model Load/Inference UI must be capability-gated. LLMs may expose prompt/sampling/speculation, Embedding models expose pooling, Drafter models are configured from the target LLM, and DECISION models do not expose chat-generation controls.
- MTP is shown and launched only for LLM targets with detected MTP support. External draft-model speculation is a target-side configuration because compatibility depends on the selected target/draft pair.
- Treat reasoning as multiple capabilities rather than one boolean: thinking toggle, effort levels, token budget, and reasoning preservation may have different support. Do not show unsupported controls.
- Request-time inference defaults must not also be forced as llama-server sampling/reasoning launch flags; otherwise live edits cannot reliably override worker-global defaults.
- Persist Server Settings across launches in TideStudio SQLite.
- Numeric server settings inputs that users may clear while editing must keep a string draft instead of coercing every keystroke with `Number(...)`; the default server port is 3456.
- Default model reasoning budget is 1024 unless a saved per-model value overrides it.
- Loaded-model cards expose a compact copy action for the exact public API model ID; successful copy actions should switch to a checkmark briefly, including the public API endpoint copy control.
- Keep llama.cpp's Web UI disabled for managed workers with `--no-webui`.
- Do not commit downloaded GGUF model weights or the generated llama.cpp runtime. Root Git ignore rules keep `models/` and `studio/runtime/llama.cpp/` local; `npm run prepare:llama` restores the pinned upstream `b11429` Windows x64 CUDA runtime for fresh clones.
- If `--gpu-layers` is high but prompt processing is unexpectedly slow, verify `llama-server --list-devices` and `llama-bench` backend output before changing offload settings. A prior local runtime contained 133-byte Git LFS pointer files in place of `ggml-cuda.dll`/cuBLAS, causing silent CPU fallback despite `--gpu-layers 9999`. `prepare-llama` must reject non-PE CUDA files; managed worker launch must fail clearly if GPU offload is requested without a detected CUDA device. ModernBERT/DECISION encoder workers should use one slot and up to 8192-token batch/ubatch instead of generic auto-parallel/512-ubatch defaults.
- Show detected quantization in loaded-model cards when known.
- Render repository README/model-card Markdown properly in the Model Search right inspector for both Hugging Face and ModelScope.
